SLIDE 02 OF 08  —  WHAT IS DATA FORMAT
What is a data format?
Before XML and JSON — let us understand the concept
Think of it like this — if you write a letter in Urdu and send it to someone who only reads English, they cannot understand it. Data formats solve this exact problem between computers.
A data format is an agreed way of writing information
so any computer or program can read and understand it
Without a format — data is just random text with no meaning
With a format — both sides know exactly where each piece of information is
Common formats you may have heard of: CSV, XML, JSON, YAML
Each has its own rules and best use cases
SLIDE 03 OF 08  —  HISTORY
A brief history — where did they come from?
Understanding why each format was created
1996
XML born
W3C created XML to share data between different systems
It came from HTML — but HTML was for displaying, XML was for storing
1999
XML became the standard for SOAP web services and enterprise systems
Banks, hospitals, governments — everyone used XML
2001
JSON born
Douglas Crockford created JSON — said "XML is too heavy for the web"
JSON was simpler, shorter, and easier for JavaScript to use
2010+
JSON became the standard for REST APIs and modern web apps
Today — WhatsApp, Google Maps, Twitter all use JSON. XML still used in older systems
SLIDE 04 OF 08  —  XML BASICS
What is XML?
eXtensible Markup Language — a way to describe data using tags
Uses opening and closing tags — just like HTML
<name>Ali</name>
Every tag you open must be closed
This is called well-formed XML
Tags are case sensitive
<Name> and <name> are different
One root tag wraps everything
Like a folder containing all files
<!-- XML example --> <student> <name>Ali</name> <age>20</age> <city>Karachi</city> <grade>A</grade> </student>
SLIDE 05 OF 08  —  JSON BASICS
What is JSON?
JavaScript Object Notation — a lightweight way to store data using key-value pairs
Data is written as key and value pairs
"name": "Ali"
Curly braces {} hold one object
Square brackets [] hold a list
Keys must always be in double quotes
"name" not name
Much shorter than XML for the same data
Faster to send over the internet
// JSON example { "name": "Ali", "age": 20, "city": "Karachi", "grade": "A" }

SLIDE 07 OF 08  —  WHEN TO USE WHICH
When should you use XML vs JSON?
Both are useful — the situation decides which one to pick
Use XML when
Working with older systems like banks or government software
Document needs strict validation and rules (XSD schema)
Data has complex structure with attributes
Working with SOAP web services
Use JSON when
Building a modern web or mobile application
Calling or creating a REST API
Speed matters — JSON is lighter and faster
Working with JavaScript — JSON is natively supported
